# Buzan-style Mind Map

Create a radiant, visual Mind Map following Tony Buzan's method rather than a
boxed tree that merely happens to radiate from a center. Read
[references/mindmap-basics.md](references/mindmap-basics.md) before creating or
materially restructuring the map.

This skill requires Nomad Canvas Dynamic Tools in the active task. If they are
unavailable, explain that the user needs to open or start a Canvas Skin task;
do not substitute an external or offline canvas.

## Workflow

1. Clarify the subject, purpose, and source material.
2. Plan a central image and the main associations that radiate from it.
3. Build connected, organic branches with one keyword or key image per branch.
4. Use color, images, hierarchy, and associations as meaningful parts of the
   thinking method.
5. Inspect relevant existing Canvas content, then create or revise the map with
   the current Canvas tools.
6. Inspect the result against the Buzan-style checklist and correct material
   violations or readability problems.

When creating a new map, use built-in ImageGen for an appropriate central image
unless it is unavailable, cannot produce a Canvas-accessible asset, or the user
requests otherwise. When revising a map, preserve a suitable existing central
image; generate one only when it is missing or unsuitable, or when the user asks
for a replacement. Keep important words as editable Canvas text; the topic label
may sit below the illustration. Insert only an image asset that the current
Canvas tool schema can access, and never invent an asset path. ImageGen may also
be used for selected branch illustrations.

Preserve the user's information when revising an existing map. If bringing it
closer to the Buzan method would require a wholesale redesign, explain that
tradeoff instead of silently discarding content. Follow the current
Canvas-scoped instructions and tool schemas for operational details.
